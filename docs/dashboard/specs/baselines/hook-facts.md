# Hook facts — measured by T0.01

Measured 2026-10-05 with Claude Code 2.1.289 (Claude Code), headless `claude -p --plugin-dir <spike>`, Windows 11, Node v22.22.3, hooks run from `D:\own-plugin\taskify-plugin`. Hook timestamps are epoch ms from `Date.now()`.

| Fact | Result | Evidence |
|---|---|---|
| (a) tool hooks in subagents | **Yes.** PreToolUse and PostToolUse fire for tool calls made inside a subagent (`echo sub-1` produced both). They also fire for the harness-internal `SubagentHandback` tool inside the subagent. Run A counts: PreToolUse 5, PostToolUse 5, SubagentStart 1, SubagentStop 1, of which 4 tool lines were inside the subagent. In Run A the 12 hook lines were: main `echo main-1` Pre+Post, main `Agent` Pre+Post, `SubagentStart`, subagent `echo sub-1` Pre+Post, subagent `SubagentHandback` Pre+Post, `SubagentStop`, main `echo main-2` Pre+Post. The main-session `Agent` PostToolUse arrived before `SubagentStart`, so the Agent call returned immediately and the subagent ran in the background. **Caveat:** the measured subagent was launched in the background (Agent `tool_response.status` was `async_launched`; `run-a.json` has `started_in_background:1`). Foreground (synchronous) subagents were not measured; T3.01 should confirm the foreground case. | Run A `hooks.jsonl`: Pre `tool_name":"Bash"`, `tool_input.command":"echo sub-1"`, with `agent_id":"a1c0dddd7300012dd"` (see Raw samples) |
| (a) subagent identity fields | Tool-hook stdin made inside a subagent carries two extra fields, `agent_id` (e.g. `a1c0dddd7300012dd`) and `agent_type` (e.g. `general-purpose`). Main-session tool-hook stdin has **neither** field, so "field absent" means main session. | Pre `echo sub-1`: `"agent_id":"a1c0dddd7300012dd","agent_type":"general-purpose"`; Pre `echo main-1`: no such keys |
| (a) session_id inside subagent | **Same as the main session.** All 12 lines carry `session_id` `d74fe789-4c82-47af-8c28-21c10033b858`, including subagent lines, so matching the marker on `session_id` alone keeps subagent events. | Run A: one distinct `session_id` across all 12 lines; also equals `CLAUDE_CODE_SESSION_ID` env |
| (b) SubagentStart fields | `session_id, transcript_path, cwd, prompt_id, agent_id, agent_type, hook_event_name`. It names the agent type. It has no description or prompt text. | Raw samples, SubagentStart line |
| (b) SubagentStop fields | `session_id, transcript_path, cwd, prompt_id, permission_mode, agent_id, agent_type, effort, hook_event_name, stop_hook_active, agent_transcript_path, background_tasks, session_crons`. `background_tasks` is an array with one item `{id, type:"subagent", status:"running", description:"Run echo sub-1", agent_type}`. Its `prompt_id` differed from SubagentStart's (`1f1678d9-…` vs `8be09019-…`). | Raw samples, SubagentStop line |
| (c) AskUserQuestion in fork | not measured — design does not depend on it (U1) | Not measurable headless; no headless method found |
| (d) async option | **works.** With `"async": true` a 3000 ms PostToolUse hook no longer delays the next tool call. Sync run: end(b-1)=1791196080871, PreToolUse(b-2)=1791196082954 (b-2 started 2083 ms after the hook ended, so it waited). Async run: end(b-1)=1791196107732, PreToolUse(b-2)=1791196106705 (b-2 started 1027 ms before the b-1 hook ended, so it did not wait). Both async hook invocations completed (both wrote their end time) and overlapped (starts 1791196104721 and 1791196106885). | `out/sleep-sync.jsonl`, `out/sleep-async.jsonl`, `out/pre-b-sync.jsonl`, `out/pre-b-async.jsonl` |
| no-op hook cost | A Node script that only does `existsSync('.taskify/active-run.json')`: spawn wall time over 10 runs, median 54.4 ms, max 59.5 ms (runs: 59.5 55.7 53.2 57.6 55.5 53.0 49.9 51.0 53.4 58.0). Median in-process `boot_ms` of the 12 Run A hook lines (dump.mjs, after Node start): 28.9 ms, max 39.1 ms. The in-session wall overhead per hook was not isolated separately; with Pre and Post that is about 2 x 54 ms per tool call on the author's machine. | Node `spawnSync` timing of `hooks/noop.mjs`; `boot_ms` field of `hooks.jsonl` |

In the implementer's own Bash tool (this subagent session, not a headless run) it is `unset` (not measured in a session with the plugin loaded). | `env.CLAUDE_PROJECT_DIR` in every hook line; `bash-tool env: CLAUDE_PLUGIN_ROOT=unset CLAUDE_PROJECT_DIR=unset` |
| CLAUDE_PLUGIN_ROOT | **Set for hooks**, with forward slashes: `C:/Users/BS-Admin/AppData/Local/Temp/taskify-spike-1791196007276`. In the implementer's own Bash tool it is `unset` (not measured in a session with the plugin loaded). | `env.CLAUDE_PLUGIN_ROOT` in every hook line; same Bash-tool line as above |

## Consequence for T3.01

- **(a) is positive**, so the `05` fallback (SubagentStart/SubagentStop only, drop the tool hooks) does **not** apply. Tool hooks stay in `hooks.json` and T2.03's activity panel can show per-subagent tool calls.
- Identify a subagent by `agent_id` and `agent_type` in stdin; absent means the main session. `session_id` is the same inside subagents, so the marker's `session_id` match keeps subagent events (the "different session_id" branch of the stale-marker entry does not apply).
- `atype` can be filled from `agent_type` on SubagentStart/SubagentStop and on tool hooks; `SubagentStart` has no prompt or description.
- **Foreground not measured.** The measured subagent was launched in the background (Agent `tool_response.status` `async_launched`; `run-a.json` `started_in_background:1`). Foreground (synchronous) subagents were not measured; T3.01 should confirm the foreground case.
- `background_tasks` was observed only on a background agent's SubagentStop; whether it is present (or empty) for foreground agents is unmeasured. It is the session's list of background tasks (match by `id == agent_id`). Its `status` is not a completion signal (it read `running` on SubagentStop). Do not rely on it for the description; use the Agent PreToolUse `tool_input.description` instead. Agent PreToolUse has no `agent_id`; in the measured background case the Agent PostToolUse `tool_response` carries both `agentId` and `description`, which links the description to the subagent (background case only seen).
- `"async": true` **works**, so the entries become async per `03` §0. With `"async": true`, events.jsonl lines may be out of event order; readers sort by `t` (approximate; `t` is hook run time). The PostToolUse JSON has no top-level `success` field; per `01` §2d, `ok` is omitted.
- Hook commands run under Git Bash on Windows, so a `2>/dev/null || true` wrapper is valid. Hooks see `CLAUDE_PROJECT_DIR` and `CLAUDE_PLUGIN_ROOT`; the Bash tool of this session did not (not measured in a session with the plugin loaded).
- The PreToolUse-vs-cost open decision stays with the user at T3.01, with a no-op spawn of about 54 ms median per hook.
