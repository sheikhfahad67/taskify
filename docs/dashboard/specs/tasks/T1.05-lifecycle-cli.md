# T1.05 — cli.mjs starts a detached server once per repo, reuses it, and stops it cleanly on any OS

## Objective

`node dashboard/cli.mjs start --root <dir>` returns within 5 s with a JSON line holding a
`http://127.0.0.1:<port>/?t=<token>` URL while the server keeps running detached after the CLI
exits. A second `start` reuses it (`"reused": true`, same pid). `status` and `url` report it.
`stop` ends it and removes `dashboard.json`. Nothing uses POSIX-only signals or shell commands.

## Preconditions

| # | Precondition | Command | Expected |
|---|---|---|---|
| P1 | T1.04 is terminal | `grep '^status:' docs/dashboard/specs/tasks/T1.04-*.md` | `status: done` |
| P2 | Server tests green | `node --test "dashboard/test/server-*.test.mjs" 2>&1 \| grep "^# fail"` | `# fail 0` |

## Scope

### Create
- `dashboard/cli.mjs` — commands `start [--root] [--port]`, `stop [--root]`, `status [--root]`,
  `url [--root]` exactly as `01` §4, plus usage error → exit 2. `start`:
  token = `crypto.randomBytes(32).toString('base64url')`; spawn
  `process.execPath [<this dir>/server.mjs, --root, <root>, --port-start, <port|4317>]` with
  `{ detached: true, stdio: 'ignore', windowsHide: true, env: { ...process.env, TASKIFY_DASHBOARD_TOKEN: token } }`,
  then `child.unref()`; poll for `dashboard.json` every 100 ms up to 5 s; confirm with
  `/api/health`. Reuse rule and stop rule exactly as `01` §4 and `05` §Windows (server pid killed
  only after `/api/health` returns that pid; a stale `dashboard.json` whose server does not answer is
  removed and `start` proceeds). `--public` is accepted but handled by T1.07 — until then it prints
  `"public_url": null`. The `review`, `resolve`, `run-start`, `run-end` commands are T1.06.
- `dashboard/test/cli.test.mjs` — tests named below.

### Explicitly out of scope
- `review`, `resolve`, `run-start`, `run-end` — T1.06. Tunnel — T1.07.
- An `--open` browser flag — not planned (`01` §1 "Not added").

## Implementation steps

1. Write `cli.mjs` with a small argument parser (no dependencies) and the four commands.
2. Use `process.kill(pid)` for stopping (TerminateProcess on Windows) and `process.kill(pid, 0)`
   only as a quick liveness hint, never as proof.
3. Tests (exact names), each on a fresh `copyFixture` root and each calling `stop` in `after()`:
   `start returns a tokenized local url`, `server survives the cli exiting`,
   `second start reuses the server`, `status and url report the running server`,
   `stop ends the server and removes dashboard.json`, `stale dashboard.json is replaced`,
   `unknown command exits 2`.
   The stale test writes a `dashboard.json` with a dead pid and a closed port, runs `start`, and
   asserts a new server answers.

### Findings

- **R-1** — **Severity:** Important
  - **Claim:** if the server exits at once (all ports 4317–4326 busy, bad port, startup crash) `start` polls the full 5 s and reports "did not become ready", losing the cause; a spawn `'error'` is unhandled and crashes the CLI; on a real timeout the detached child is orphaned.
  - **Evidence:** cli.mjs:66-82 (no `exit`/`error` listeners).
  - **Required fix:** listen for `exit`/`error` before polling; on early exit print a clear stderr message (code, likely busy ports) and exit 1; on timeout kill the child (try/catch).
- **R-2** — **Severity:** Minor — `--port` validated after reuse/removeInfo; `start --port abc` can print `reused:true` or delete dashboard.json; `--port`/`--public` silently accepted on other commands; `--root --port` swallows the flag (cli.mjs:17-26, 54-64).
- **R-3** — **Severity:** Minor — two concurrent `start` calls can orphan a server whose idle exit later deletes the live server's dashboard.json (cli.mjs:58-80; server.mjs:218-224). Follow-up (with T1.03 R-3).
- **R-4** — **Severity:** Minor — `process.kill` in `stop` can throw ESRCH/EPERM uncaught, leaving dashboard.json (cli.mjs:89).
- **R-5** — **Severity:** Observation — `--port` near 65535 makes the server call `listen(65536)` and crash.
- **R-6** — **Severity:** Observation — no test for a live unrelated pid, or for early exit; temp roots not removed.
- **R-7** — **Severity:** Observation — 5 s wait counts iterations, not wall-clock time.

**Round 2 (2026-10-05):** verdict **`approved`**. R-1, R-2, R-4, R-5, R-7 resolved; R-3 deferred (Follow-ups, paired with T1.03 R-3); R-6 partly (early-exit test added). Suite re-run by orchestrator: 49 pass, 0 fail; `start --port abc` / `status --port 1` exit 2.

- **N-1** — **Severity:** Minor — AC2 Expected says 7 tests; there are now 8. The 8th (`start reports early server exit quickly`) was required by R-1; Expected text left as written.
- **N-2** — **Severity:** Observation — the new test errors loudly (never passes falsely) if a port in 47100–47109 is taken or reserved by Windows.
- **N-3** — **Severity:** Observation — an in-flight health call can stretch the 5 s limit to ~7 s.
- **N-4** — **Severity:** Observation — `stop` can report `stopped: true` if kill fails with EPERM and the server still answers; unlikely.
