# T4.03 — taskify-implementer offers the dashboard, gates on review state, and marks the run for the hooks

## Objective

`taskify-implementer`, after the plan is picked:

1. **Asks** (`AskUserQuestion`) whether to open the dashboard: `Yes — local`, `Yes — public link`,
   `No`. On yes, runs `cli.mjs start [--public]` and shows the URL (and for public, the warning).
2. In **Step 2**, runs `cli.mjs review --plan <plan>`. If `open_comments` is non-empty it lists them
   (file, heading, text) and asks: `Address them first`, `Run anyway`, `Stop`. "Address them first"
   means: update the plan docs/specs as each comment asks (the user chose this, so it is not the
   forbidden "edit the bar to pass"), show what changed, run `cli.mjs resolve --by
   taskify-implementer --note …` for each, then redo grounding. If `approved` is false it warns and
   asks `Run without approval` / `Stop`; if approved but `docs_changed_since_approval` is non-empty,
   it names those files and asks the same.
3. Checks `git check-ignore -q .taskify/`; if not ignored, asks once whether to add `.taskify/` to
   `.gitignore`, and edits it only on yes.
4. Runs `cli.mjs run-start --plan <plan>` immediately before Step 3's first dispatch (and again on
   resume), and `cli.mjs run-end` whenever the run state becomes `paused`, `stopped-by-user`, or
   `complete`.
5. On `complete`, if this run started the dashboard, asks whether to stop it.

All CLI calls use `node "<base directory>/../../dashboard/cli.mjs" …` (B9). If `node` is missing,
the dashboard and review steps are skipped with a one-line note and the run continues as in 0.1.0.
