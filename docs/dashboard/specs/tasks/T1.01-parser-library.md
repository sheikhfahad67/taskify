# T1.01 — parse.mjs turns a taskify plan folder into structured data, tolerating broken files

## Objective

`dashboard/lib/parse.mjs` exports pure functions that turn the text of a spec, a specs README, a
PROGRESS.md, and an events.jsonl into the data `/api/plan` returns (`01` §3), plus `findPlans(root)`
for plan discovery. None of them throws on malformed input. A real fixture plan set exists under
`dashboard/test/fixtures/plan-basic/` and `node --test` proves the numbers.

## Preconditions

| # | Precondition | Command | Expected |
|---|---|---|---|
| P1 | T0.01 is terminal | `grep '^status:' docs/dashboard/specs/tasks/T0.01-*.md` | `status: done` |
| P2 | Node ≥ 22 for the test glob | `node --version` | `v22.` or newer |
| P3 | No dashboard code yet | `test ! -e dashboard && echo absent` | `absent` |

## Scope

### Create
- `dashboard/lib/parse.mjs` — exports:
  - `parseFrontmatter(text) → { data, body }` — the YAML subset the template uses: `key: value`,
    trailing `# comment` stripped, inline lists `[]` / `[T1.01, T1.02]`, block lists (`- item`), one
    level of nested maps (`implementer:` / `  agent: …`).
  - `parseSpec(text) → { id, phase, title, status, depends_on, touches, ac_total, ac_verified, acs: [{ id, name, type, verified }], verdict }`
    (`ac_total` = `### AC` headings; `ac_verified` = `- **Verified:** [x]` lines; `verdict` per `01` §3).
  - `parseReadme(text) → { index: [{ id, phase, title, status, review, depends_on }], waves: [{ wave, tasks: [ids] }] }`.
  - `parseProgress(text) → { run_state, current_task, current_step, last_updated, resume_note, log: [{ time, task, event, note }] }`
    (HTML comments stripped from values).
  - `parseEvents(text, limit = 200) → [event]` — skips any line that is not valid JSON; returns the last `limit`.
  - `fixRounds(log, taskId) → number` — log rows for that task whose `event` contains `changes_requested`.
  - `findPlans(root) → [{ id, dir }]` — walk per `01` §3 (skip `node_modules`, `.git`, `.taskify`; depth ≤ 6; id uses `/`).
  Imports only `node:fs` and `node:path`.
- `dashboard/test/helpers.mjs` — `copyFixture(name) → root` (makes
  `root = fs.mkdtempSync(path.join(os.tmpdir(), 'taskify-'))` and copies `fixtures/<name>` to
  `<root>/docs/<name>/`, including `.taskify/`, so the plan's id is `docs/<name>`). Server helpers
  are added by T1.03.
- `dashboard/test/fixtures/plan-basic/` — a real plan set:
  - `00-overview.md` — H1 `# Fixture Plan — Overview`; a `## Goal` section; one line containing
    `<script>window.__xss = 1</script>` (used by T2.02).
  - `04-execution-phases.md` — H1 and a `## Phase 1 — Alpha` section.
  - `specs/tasks/README.md` — wave graph code block with `Wave 1   T1.01 → T1.02` and
    `Wave 2   T2.01 ∥ T2.02`; task index with those 4 rows.
  - `specs/tasks/_TEMPLATE.md` — a copy of `docs/dashboard/specs/tasks/_TEMPLATE.md` (must be ignored as a task).
  - `specs/tasks/T1.01-alpha.md` — `status: done`, 3 ACs all `[x]`, verdict `approved`.
  - `specs/tasks/T1.02-beta.md` — `status: in_review`, 3 ACs, 2 `[x]`, verdict `pending`.
  - `specs/tasks/T2.01-gamma.md` — `status: changes_requested`, 2 ACs, 0 `[x]`, verdict `changes_requested`.
  - `specs/tasks/T2.02-delta.md` — `status: pending`, `depends_on: [T2.01]`, 2 ACs, 0 `[x]`, verdict `pending`.
  - `specs/tasks/PROGRESS.md` — implementer template shape: `running`, `T1.02`, `review`; log of 6
    rows of which 2 are `T2.01 | changes_requested`.
  - `.taskify/review.json` — `01` §2c shape: comment `c_00000001` on `00-overview.md`, anchor
    `Goal`, text `Goal should name the invariant.`, open; comment `c_00000002`, resolved;
    `approvals: []`.
  - `.taskify/events.jsonl` — 5 valid lines (`01` §2d), in order: `SubagentStart` aid `a1` atype
    `general-purpose`; `PreToolUse` aid `a1` tool `Bash` sum `node --test`; `PostToolUse` aid `a1`
    tool `Bash`; `SubagentStart` aid `a2` atype `feature-dev:code-reviewer`; `SubagentStop` aid
    `a2` — then a half-written line `{"t":"2026-10-05T10:00:09.000Z","ev":"PreTo` with no newline.
    (So exactly one subagent, `a1`, is still open; T2.03 relies on this.)
- `dashboard/test/parse.test.mjs` — tests named below.

### Explicitly out of scope
- Reading or writing `review.json` — T1.02.
- Any HTTP code, last-good cache — T1.03.
- `.gitignore` negation for the fixture `.taskify/` — T4.04 (until then nothing ignores it).

## Implementation steps

1. Write the fixture files first, using the real template shapes (`skills/taskify/references/task-spec.md`
   body, the implementer's PROGRESS.md template).
2. Write `parse.mjs` per Scope. Every function wraps its work so malformed input gives empty/`null`
   fields, never an exception.
3. Write `parse.test.mjs` with these test names (exact): `parseSpec counts ACs and verdict`,
   `parseFrontmatter handles inline and block lists and nested maps`, `parseReadme reads index and waves`,
   `parseProgress reads fields and log`, `parseEvents skips a half-written last line`,
   `fixRounds counts changes_requested rows`, `findPlans finds the fixture and skips node_modules`,
   `parsers never throw on garbage`. The `findPlans` test creates `node_modules/x/specs/tasks/README.md`
   inside the temp copy's root and asserts it is not returned. The garbage test feeds each parser
   `''`, `'---\n:::\n'`, and 10 KB of random bytes.
