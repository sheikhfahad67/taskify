# T3.02 — Phase 3 gate — a real Claude Code session records subagent activity only when a run is active

## Objective

With this repo loaded via `--plugin-dir`, a headless Claude Code session that dispatches a subagent
writes `SubagentStart`/`SubagentStop` lines (and tool lines, if `hook-facts.md` says tool hooks fire)
into the plan's `events.jsonl` when the active-run marker names that session — and writes nothing
when the marker names another session or when there is no marker.

## Preconditions

| # | Precondition | Command | Expected |
|---|---|---|---|
| P1 | T3.01 is terminal | `grep '^status:' docs/dashboard/specs/tasks/T3.01-*.md` | `status: done` |
| P2 | Headless flags exist | `claude --help \| grep -c -E -- '--session-id\|--plugin-dir'` | `2` or more |

## Scope

### Explicitly out of scope
- Fixing anything. A failing AC sets `status: blocked` with the output and names T3.01.
- Disabling the installed `taskify@fahad-marketplace` plugin. If `--plugin-dir` reports a name clash
  with it, set `blocked` and ask the user; do not change plugin settings yourself.

## Implementation steps

1. `R` = a `copyFixture('plan-basic')` root; `PLAN="$R/docs/plan-basic"`; `REPO` = this repo's
   absolute path. Run all `claude` commands with `cwd` = `R`.
2. Prompt (on stdin): `Use the Agent tool with subagent_type general-purpose and ask it to run the Bash command: echo gate-sub. Report its output.`
   Flags: `-p --plugin-dir "$REPO" --max-budget-usd 1 --allowedTools "Bash(echo:*),Agent" --session-id <uuid>`.
3. Three runs: matching marker, other-session marker, no marker — see the ACs.
