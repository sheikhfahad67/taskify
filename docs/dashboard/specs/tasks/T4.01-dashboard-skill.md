# T4.01 — /taskify:dashboard starts, stops and reports the dashboard from any session

## Objective

`/taskify:dashboard start [--public] [--port <n>]`, `stop`, `status`, and `url` work in any Claude
Code session in a project. The skill finds the CLI from its own base directory
(`<base directory>/../../dashboard/cli.mjs`, B9), checks `node --version` first, runs the matching
`cli.mjs` command with `--root` = the current project directory, and tells the user the result in
one or two short lines: the local URL (with token), and for `--public` the public URL plus the
warning that anyone with the link can read the plan docs and add comments or approve. With no
argument it behaves as `status`, and if nothing runs, it says how to start.

## Scope

### Create
- `skills/dashboard/SKILL.md` — frontmatter exactly `03` §4. Body sections:
  1. **Arguments** table (`start`, `--public`, `--port`, `stop`, `status`, `url`, no argument).
  2. **Find the CLI** — "This skill's base directory is shown when it loads. The CLI is
     `<base directory>/../../dashboard/cli.mjs`." Run `node --version`; if it fails, say Node 20+ is
     needed and stop.
  3. **Run** — one `node "<cli>" <command> --root "<project dir>" [flags]` call; parse its JSON.
  4. **Report** — local URL; public URL and the exact warning
     `Anyone with this link can read these plan docs and add comments or approve the plan.`;
     install hints from stderr when `--public` found no tunnel tool (the local URL still works);
     for `stop`, what was stopped.
  5. **Rules** — never start a tunnel without `--public`; never print the token apart from inside the
     URL; never edit plan docs, specs, or `.gitignore`.

### Explicitly out of scope
- Changes to `taskify` or `taskify-implementer` — T4.02, T4.03.
- README / CHANGELOG — T4.04.
