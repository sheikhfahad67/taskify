# T2.02 — The review view renders plan docs safely and lets a reviewer comment, resolve-view and approve

## Objective

`#/plan/<id>/review` shows: a document list (plan docs `0N-*.md` first, then the specs README, then
specs in id order, then PROGRESS.md), the selected document rendered with marked, and a comment
panel. Raw HTML in a document shows as text and never runs. Every `h1`–`h3` gets an `id` slug and a
"Comment" button that opens the form pre-anchored to that heading. Comments for the open file are
listed (open first; resolved hidden behind a "Show resolved" toggle), with a per-file open-comment
count in the document list. An "Approve plan" button records an approval and the header then shows
"Approved by <name> at <time>". A name field is remembered in `localStorage` (`taskify.author`,
`try/catch`). Polling refreshes comments without losing a half-typed comment.

## Scope

### Create
- `dashboard/public/review.js` — ES module exporting:
  - `renderMarkdown(md) → html` — uses `globalThis.marked`; a `marked.use({ renderer: { html(token) { … } } })`
    override returns the token's raw text HTML-escaped; headings get `id="<slug>"` and a
    `<button class="comment-btn" data-anchor="<heading text>">Comment</button>`.
  - `slug(text)` — lowercase, non-alphanumerics to `-`, trimmed.
  - `mount(el, { planId, api, onPoll })` — the view. POSTs to `/api/comments` and `/api/approve`
    with `Content-Type: application/json`. Shows server error messages (400/413) next to the form.
  No `innerHTML` with unescaped server strings other than `renderMarkdown` output; comment text and
  names are inserted with `textContent`.
- `dashboard/test/ui-review.test.mjs` — tests named below.

### Edit
- `dashboard/public/app.css` — styles for the review layout (three panes on wide screens, stacked
  under 800 px).

### Explicitly out of scope
- Resolving comments from the browser — resolution is Claude's action via `cli.mjs resolve` (U4).
  The browser only shows resolved state.
- Editing plan docs — never.

## Implementation steps

1. Write `review.js` and its CSS.
2. Tests (exact names), on a fresh fixture copy each:
   - Node-only (no browser): `renderMarkdown escapes raw html`, `renderMarkdown adds heading ids and comment buttons`
     (load marked with `createRequire` and set `globalThis.marked` before importing `review.js`).
   - Browser: `review view renders the overview and its open comment`,
     `raw script in a doc is shown as text and does not run` (evaluate `window.__xss === undefined`
     and that the page text contains `<script>window.__xss = 1</script>`),
     `comment button anchors the form and posting adds the comment` (click the `Goal` heading's
     button, type, submit; then the DOM lists it and `review.json` on disk has 3 comments with
     `anchor: "Goal"`), `approve button records approval and shows it`,
     `resolved comments are hidden until toggled`, `polling keeps a half-typed comment`.
