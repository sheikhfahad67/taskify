# T1.04 — The server accepts comments, resolutions and approvals, writing only review.json

## Objective

`POST /api/comments`, `POST /api/comments/<cid>/resolve`, and `POST /api/approve` work as `01` §3
defines, through `review-store.mjs`. A POST without the token, without `Content-Type:
application/json`, with a foreign `Origin`, over 64 KB, or with invalid fields is refused with the
right status, and **no file other than `<plan>/.taskify/review.json` changes** on any request.

| # | Precondition | Command | Expected |
|---|---|---|---|
| P1 | T1.03 is terminal | `grep '^status:' docs/dashboard/specs/tasks/T1.03-*.md` | `status: done` |

## Scope

### Edit
- `dashboard/server.mjs` — add the three POST routes. Order of checks: token (`401`) → method and
  route (`404`/`405`) → `Content-Type` starts with `application/json` (`415`) → `Origin`, if
  present, has the same host as `Host` (`403`) → body ≤ 64 KB, counted while streaming (`413`) →
  JSON parse (`400`) → plan id allow-listed (`404`) → store call (`EINVAL` → `400`, `ENOENT` →
  `404`). Responses are JSON. `author`/`by` default to `"browser"` when empty.

### Create
- `dashboard/test/server-write.test.mjs` — tests named below.

### Explicitly out of scope
- The CLI `resolve` command — T1.06 (it uses the store directly, not HTTP).
- UI forms — T2.02.

## Implementation steps

1. Add the routes in `server.mjs` with the check order above.
2. Tests (exact names): `post comment returns 201 and persists`, `resolve marks comment resolved`,
   `resolve unknown id is 404`, `approve returns 201 and plan reads approved`,
   `post without token is 401`, `post without json content type is 415`,
   `post with foreign origin is 403`, `post over 64KB is 413`, `invalid fields are 400`,
   `writes touch only review.json`.
3. The last test hashes every file under the temp root (excluding `.taskify/review.json`,
   `.taskify/review.json.lock`, and `.taskify/dashboard.json`) before and after a run of all three
   POSTs, and asserts the hashes are identical.
