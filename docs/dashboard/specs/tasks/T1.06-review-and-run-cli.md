# T1.06 — cli.mjs gives skills one command each to read the review, resolve a comment, and mark a run

## Objective

The skills never parse or write `review.json` or the marker by hand. `cli.mjs review --plan <dir>`
prints the summary the implementer's Step 2 needs; `resolve` marks one comment resolved (server
running or not); `run-start` writes `<root>/.taskify/active-run.json` with the current session id
and empties `<plan>/.taskify/events.jsonl`; `run-end` removes the marker. All four work from any
shell because the CLI reads `CLAUDE_CODE_SESSION_ID` itself (B6).

| # | Precondition | Command | Expected |
|---|---|---|---|
| P1 | T1.05 is terminal | `grep '^status:' docs/dashboard/specs/tasks/T1.05-*.md` | `status: done` |
| P2 | Store exports the summary | `grep -c "reviewSummary" dashboard/lib/review-store.mjs` | ≥ 1 |

## Scope

### Edit
- `dashboard/cli.mjs` — add `review`, `resolve`, `run-start`, `run-end` exactly as `01` §4.
  `review` prints `reviewSummary(planDir)` as JSON. `resolve` calls `resolveComment` with
  `by` defaulting to `"claude"`; unknown id → stderr message, exit 1. `run-start` requires `--plan`
  pointing at a folder containing `specs/tasks/README.md` (else exit 2); `session_id` =
  `--session` or `CLAUDE_CODE_SESSION_ID` or `null`; writes the marker atomically (tmp + rename);
  truncates `events.jsonl` (creating `.taskify/` if needed). `run-end` deletes the marker, ignoring
  `ENOENT`.
- `dashboard/test/cli.test.mjs` — append tests named below.
