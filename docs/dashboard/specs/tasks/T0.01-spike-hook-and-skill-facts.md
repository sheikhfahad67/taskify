# T0.01 — Measure what plugin hooks receive in a real session and record it as a baseline

## Objective

`docs/dashboard/specs/baselines/hook-facts.md` holds measured answers, each backed by raw stdin or
timing captured from a real headless Claude Code session: whether tool hooks fire inside subagents
and how a subagent is identified, the stdin fields of SubagentStart/SubagentStop, whether
`"async": true` stops a slow hook from delaying the tool call, the in-session cost of a no-op Node
hook, which env vars hooks and the Bash tool see, and which shell runs hook commands on Windows.
`05` is corrected in place with each answer. No code lands in the repo.

## Implementation steps

1. Create the spike plugin folder in the OS temp dir. Shell variables do not survive between Bash
   calls, so note its absolute path and substitute it wherever this spec writes `$SPIKE`
   (including in the AC commands). It holds:
   - `.claude-plugin/plugin.json`: `{"name":"taskify-spike","version":"0.0.0","description":"T0.01 spike"}`
   - `hooks/dump.mjs`: reads all of stdin, then appends one JSON line to
     `<folder of this script>/../out/hooks.jsonl` with `{t: Date.now(), boot_ms: Date.now() -
     performance.timeOrigin, stdin: <parsed stdin or raw string>, cwd: process.cwd(), env: {CLAUDE_PROJECT_DIR,
     CLAUDE_PLUGIN_ROOT, CLAUDE_CODE_SESSION_ID, SHELL, ComSpec}}`; exits 0; writes nothing to stdout.
   - `hooks/hooks.json`: `SubagentStart`, `SubagentStop`, `PreToolUse`, `PostToolUse`, each running
     `node "${CLAUDE_PLUGIN_ROOT}/hooks/dump.mjs"` (timeout 10); plus on `PreToolUse` a second entry
     with command `echo "shell=$0" >> "${CLAUDE_PLUGIN_ROOT}/out/shell.txt"`.
2. **Run A (facts).** From the repo root:
   `echo "Run the Bash command: echo main-1. Then use the Agent tool with subagent_type general-purpose and ask it to run the Bash command: echo sub-1, and report the output. Then run the Bash command: echo main-2." | claude -p --plugin-dir "$SPIKE" --max-budget-usd 1 --output-format json --allowedTools "Bash(echo:*),Agent" > "$SPIKE/out/run-a.json"`.
   The prompt goes on stdin because `--allowedTools` takes several values and would swallow a
   trailing prompt argument.
   Also run `echo "bash-tool env: CLAUDE_PLUGIN_ROOT=${CLAUDE_PLUGIN_ROOT:-unset} CLAUDE_PROJECT_DIR=${CLAUDE_PROJECT_DIR:-unset}"` in your own Bash tool and keep the output.
3. **Run B (async).** Replace `hooks/hooks.json` with a single `PostToolUse` entry, matcher `Bash`,
   running a `hooks/sleep.mjs` that records `{start, end}` (`Date.now()`) around a 3000 ms sleep to
   `out/sleep-sync.jsonl`, plus the `dump.mjs` PreToolUse entry. Run a prompt that runs
   `echo b-1` then `echo b-2`. Then add `"async": true` to the sleep entry (writing to
   `out/sleep-async.jsonl`) and run it again. For each run, compare the PreToolUse `t` of `b-2` with
   the sleep `end` of `b-1`: sync means PreToolUse(b-2) ≥ end(b-1).
4. **Cost.** Re-run B4's measurement: 10 runs of a Node script that only does
   `existsSync('.taskify/active-run.json')` and exits; report median and max. Also report the
   median `boot_ms` of Run A's lines.
5. **AskUserQuestion in a fork (c).** Not measurable headless. Record `not measured — design does
   not depend on it (U1)` unless you find a headless way, in which case record what you ran.
6. Write `hook-facts.md`: H1 `# Hook facts — measured by T0.01`, a line with the date and
   `claude --version`, then one table `| Fact | Result | Evidence |` with exactly these row keys
   in the first column: `(a) tool hooks in subagents`, `(a) subagent identity fields`,
   `(a) session_id inside subagent`, `(b) SubagentStart fields`, `(b) SubagentStop fields`,
   `(c) AskUserQuestion in fork`, `(d) async option`, `no-op hook cost`, `CLAUDE_PROJECT_DIR`,
   `CLAUDE_PLUGIN_ROOT`, `stdin cwd`, `hook shell on Windows`, `PostToolUse success field`. Then a
   `## Raw samples` section pasting one full stdin line per event type (redact nothing but secrets;
   there should be none). End with `## Consequence for T3.01` listing which branch of `05` applies.
7. Edit `05` as described in Scope.
8. Delete `$SPIKE` when done (it is outside the repo; leaving it is harmless but untidy).
