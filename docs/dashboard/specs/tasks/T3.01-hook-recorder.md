# T3.01 — Plugin hooks append compact events during an active run and cost almost nothing otherwise

## Objective

`hooks/hooks.json` (`03` §0, adjusted only as T0.01's baseline and the user's PreToolUse decision
allow) runs `hooks/record-event.mjs` on SubagentStart, SubagentStop, PreToolUse and PostToolUse.
With no `<project>/.taskify/active-run.json`, the script exits 0 without reading stdin. With a
marker whose session rule matches (as `hook-facts.md` determined), it appends one `01` §2d line to
`<marker.plan>/.taskify/events.jsonl`. On any error — bad stdin, missing plan folder, unwritable
file — it still exits 0 and prints nothing.

## Scope

### Create
- `hooks/hooks.json` — `03` §0 literally, then only these changes: `"async": true` on each entry if
  row `(d) async option` says `works`; the `PreToolUse` block removed if the user said drop; the
  tool blocks removed if row `(a) tool hooks in subagents` is negative **and** main-session tool
  events alone are judged not worth it per `05` (fallback). If row `hook shell on Windows` shows a
  POSIX shell, the command may become `node "…" 2>/dev/null || true` (`05` §A hook that errors);
  record the choice.
- `hooks/record-event.mjs` — per `03` §"The script never blocks or fails a tool call". Order:
  1. `existsSync(join(process.env.CLAUDE_PROJECT_DIR ?? process.cwd(), '.taskify', 'active-run.json'))`
     — false → `process.exit(0)`.
  2. Read stdin fully (with a 1 s guard timer that exits 0), parse JSON, read the marker.
  3. Session rule from `hook-facts.md` (default: stdin `session_id` equals marker `session_id`, or the
     marker's `session_id` is `null`); no match → exit 0.
  4. Build the line per `01` §2d, mapping `aid`/`atype`/`ok` from the stdin fields the baseline names
     (`null` when absent). `sum` per the table in `01` §2d, cut to 120 characters.
  5. `appendFileSync(<plan>/.taskify/events.jsonl, line + '\n')` — create `.taskify/` if missing.
  Everything after step 1 inside `try { … } catch {}`; final `process.exit(0)`.
- `dashboard/test/record-event.test.mjs` — tests named below.

### Explicitly out of scope
- Writing the marker — `cli.mjs run-start` (T1.06) does it; the skill calls it in T4.03.
- Showing events — T2.03 already does.

   hook 66 ms; under load 78–116 / 92–146 / 90–134 ms), so the relative bar measures only the hook's own work).

A marker whose `plan` folder does not exist records nothing (the recorder never creates the plan folder; it only creates `<plan>/.taskify/`).

The literal 150 ms bar failed (297 and 401 ms) whenever the full suite ran in parallel, because every spawn was slow; standalone it passes at about the B4 figure. The spec text should be updated if the reviewer agrees. *(Superseded: the user approved the relative bar, and in fix round 2 changed the baseline to an interleaved empty `.mjs` spawn after one warm-up — see step 3.)*
