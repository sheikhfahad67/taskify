# T3.03 — A forgotten public dashboard still shuts itself down, and leaks less, before skills expose --public

Inserted at the user's request (2026-10-05) to close the Phase 1 `--public` hardening follow-ups
before T4.01 makes `--public` reachable from a skill.

## Objective

Five behaviours hold:

1. **Only authenticated requests reset the idle timer** (T1.08 F-1). A stream of `401` requests
   from the internet does not keep a forgotten public server and tunnel alive past `--idle-minutes`.
2. **Idle exit kills the recorded tunnel** — now proven by a test (T1.08 F-2).
3. **Idle exit only cleans up state it owns** (T1.03 R-3, T1.05 R-3): it kills the tunnel and
   removes `dashboard.json` only when `dashboard.json`'s `pid` equals its own `process.pid`.
4. **A `500` response carries no internal error text** (T1.04 R-2): handler and unknown store
   errors return a generic body; the detail is not sent to the client.
5. **ngrok runs without its local request inspector** (T1.07 R-7): the ngrok spawn passes
   `--inspect=false`, so the token is not logged at `127.0.0.1:4040`.

## Scope

### Edit
- `dashboard/server.mjs` — move the idle-timer reset after the token check (item 1); owner check in
  idle exit (item 3); generic `500` bodies (item 4).
- `dashboard/cli.mjs` — add `--inspect=false` to the ngrok arguments (item 5).
- Tests (add, do not rename existing):
  - `server-read.test.mjs`: `unauthenticated requests do not reset idle timer`;
    `idle exit leaves a foreign dashboard.json alone`.
  - `tunnel.test.mjs`: `idle exit kills the recorded tunnel`; extend an existing assertion or add
    one that the ngrok argument list contains `--inspect=false`.
  - `server-write.test.mjs`: `500 body has no error detail` (force an unknown store error, e.g.
    make `.taskify` a file so the store's mkdir/write fails with a non-mapped code).

### Explicitly out of scope
- The cookie name (T1.08b), parser hardening, review-store lock tokens, and other Minor follow-ups.
- cloudflared verification (AC4 of T1.07 stays deferred, user-approved).

## Implementation steps

1. Item 1: call `resetIdle()` only after auth succeeds.
2. Item 3: in idle exit, read `dashboard.json`; act only if `info.pid === process.pid`; always exit.
3. Item 4: replace `err.message` in `500` responses with a fixed short text; keep mapped store
   statuses (400/404/409/503) and their messages as they are.
4. Item 5: add `--inspect=false` to the ngrok spawn arguments.
5. Write the tests. Idle tests use `--idle-minutes` small enough to finish in a few seconds (e.g.
   `0.03` ≈ 1.8 s). Item 1 test: send a `401` request every ~300 ms and assert the server still
   exits within about 2× the idle time. Item 2 test: start the fake tunnel, record it in
   `dashboard.json` as the server's tunnel (`cmd: 'node'`), wait for idle exit, assert the fake
   tunnel pid is gone. Item 3 test: after the server starts, overwrite `dashboard.json` with a
   different `pid`; after idle exit, the file still exists unchanged.
6. Run the ACs.
