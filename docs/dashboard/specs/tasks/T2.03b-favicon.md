# T2.03b — The dashboard page requests no favicon, so page loads log no 404 and the console-error tests are stable

Inserted at the user's request (2026-10-05), before the Phase 2 gate, to fix T2.02 review
finding O-1.

## Objective

`dashboard/public/index.html` declares `<link rel="icon" href="data:,">`, which the CSP already
allows (`img-src 'self' data:`). Browsers then do not request `/favicon.ico`, so no `404` network
error is logged on page load. The favicon filters added to UI tests as a workaround are removed,
so "no console or CSP errors" assertions check the real, unfiltered error list and still pass.

## Scope

### Edit
- `dashboard/public/index.html` — add `<link rel="icon" href="data:,">` in `<head>`.
- `dashboard/test/ui-review.test.mjs`, `dashboard/test/ui-progress.test.mjs` — remove the
  `favicon` filter from console/network-error assertions (keep test names).
- `dashboard/test/ui-shell.test.mjs` — no change expected; listed only so its
  "no console or CSP errors on home" test may be adjusted if it needs to wait a moment after load
  for late network errors to arrive (so the assertion is meaningful, not lucky).

### Explicitly out of scope
- Any other follow-up.

## Implementation steps

1. Add the icon link. Remove the favicon filters.
2. Make sure each no-errors assertion waits at least ~1 s after the page is ready before reading
   the error list, so a late `/favicon.ico` request would be caught if it still happened.
3. Run the ACs.
