# T3.02b — The progress view's open subagents come from the whole events file, so busy or out-of-order agents are shown correctly

Inserted at the user's request (2026-10-05) after the Phase 2 gate. Fixes T2.03 review findings
R-6 (200-event window drops long-running subagents), R-4 (a Stop sorted before its Start keeps a
subagent open forever) and R-5 (guard non-string `aid`). Runs after T3.02, so real hook events
exist to check against.

## Objective

`GET /api/plan` returns `open_subagents`: the subagents that have a `SubagentStart` and no
`SubagentStop` with the same `aid` **anywhere** in `events.jsonl` (not only the last 200 lines),
each as `{aid, atype, started, last_tool, last_sum}` where `last_*` is the latest (by `t`) tool
event from that `aid` with a non-empty `sum`. Lines whose `aid` is not a non-empty string are
ignored for pairing. The progress view's "Open subagents" panel renders this list instead of
deriving it from the 200-event window. The "recent events" list still uses `events` (last 200).

## Scope

### Edit
- `dashboard/lib/parse.mjs` — add `openSubagents(text)` (or equivalent) that scans every line
  once, tolerates bad lines as `parseEvents` does, and applies the rules above.
- `dashboard/server.mjs` — include `open_subagents` in `/api/plan`, read from the full file with
  the same last-good caching as other files.
- `dashboard/public/progress.js` — render the panel from `open_subagents`; remove the now-unused
  client-side derivation if nothing else uses it.
- Tests (add; keep existing names): in `parse.test.mjs` — `open subagents survive beyond 200 events`
  (a Start, then 250 tool events from that aid, no Stop → still open with the latest sum) and
  `stop before start in file order still closes` (Stop line earlier in the file and earlier `t`
  than its Start → not open) and `non-string aid is ignored`; in `server-read.test.mjs` —
  `plan includes open_subagents`; adjust `ui-progress.test.mjs` only as needed for the new source.

### Explicitly out of scope
